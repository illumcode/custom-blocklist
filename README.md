# update_lists.py

Обновляет `*_ip.lst` файлы из живых источников вместо ручного копирования подсетей.

## Установка

```
pip install -r requirements.txt
```

## Запуск

`.lst`-файлы лежат в подпапке `lists/` рядом со скриптом. Запуск:

```
python3 update_lists.py                    # обновить все сервисы (пишет в ./lists)
python3 update_lists.py --list              # посмотреть, какой сервис из чего собирается
python3 update_lists.py --only telegram,youtube
python3 update_lists.py --dry-run           # показать, что изменится, ничего не писать
python3 update_lists.py --dir /путь/к/lists # если папка лежит не рядом со скриптом
```

## Как это работает

Для каждого сервиса задан рецепт (в самом скрипте, в словаре `SERVICES`):

- **resolve** — читает `<сервис>_domains.lst`, резолвит все домены через 4 публичных
  DNS (Cloudflare/Google/Quad9/OpenDNS) параллельно, берёт /24 вокруг каждого
  полученного IP.
- **asn** — тянет все анонсируемые подсети ASN через RIPEstat → ip.guide → bgpview
  (первый живой источник побеждает).
- **cloudflare** / **cloudfront** — официальные фиды провайдеров.
- **official_url** — как есть, забирает готовый список (Telegram публикует свой
  `cidr.txt` напрямую).

Результат схлопывается (`ipaddress.collapse_addresses`), из него вырезаются адреса
самих DNS-резолверов (чтобы список не увёл в туннель собственный DNS), сортируется
и сравнивается с тем, что уже лежит в `<сервис>_ip.lst` — в лог идёт, что добавилось
и что пропало.

## Что НЕ покрыто

- `tiktok_ip.lst` — сервис не включён в конфиг: не нашёл источника (ASN/фида),
  которому можно доверять в автоматическом режиме. Файл скрипт не трогает.
- Домены (`*_domains.lst`) генератор не пополняет сам — это твой ручной список,
  скрипт только резолвит то, что в нём уже есть.

## Автообновление через GitHub Actions

В `.github/workflows/update-lists.yml` лежит воркфлоу, который:

1. Раз в день (04:17 UTC, крон настраивается в файле) или вручную по кнопке
   **Run workflow** запускает `update_lists.py`.
2. Если что-то изменилось — коммитит `.lst`-файлы от имени `github-actions[bot]`
   и пушит прямо в ветку.
3. Если изменений нет — просто завершается, ничего не коммитит.

Чтобы включить:

1. Залей содержимое этого архива в свой GitHub-репозиторий (структура папок —
   как есть, `.github/workflows/...` должен остаться на своём месте).
2. В Settings → Actions → General → Workflow permissions выставь
   **Read and write permissions** (иначе `git push` из воркфлоу упадёт с 403).
3. Всё, дальше он бегает сам. Прогресс смотри во вкладке Actions репозитория.

`.gitattributes` в архиве фиксирует CRLF для `.lst`, чтобы GitHub-раннер
(Linux) не менял концы строк при коммите.

## Добавить свой сервис

В словарь `SERVICES` — новая запись:

```python
"myservice": Service(
    ip_file="myservice_ip.lst",
    domains_file="myservice_domains.lst",   # опционально
    sources=[Source("resolve"), Source("asn", asn=12345)],
),
```

Файл на диске создавать не нужно — скрипт напишет его сам при первом запуске.
